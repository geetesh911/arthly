## Changes from the spec

- **Service worker:** SvelteKit's built-in `src/service-worker.ts` replaces `@vite-pwa/sveltekit`, which doesn't support SvelteKit 3 yet. It caches the build files listed by `$service-worker`.
- **Hashing for IDs:** `@noble/hashes` gives a synchronous SHA-256, so IDs can be made without `await`.
- **KDF settings per wrap:** each passphrase wrap carries its own Argon2id settings and salt, instead of one `kdf` block for the keyring. A new passphrase gets a fresh salt, and settings can change without touching other wraps.
- **Undoing an import:** the import is replayed as if it never happened. Records it overwrote go back to their earlier version, instead of being removed. Records edited since the import stay, as the spec says.
- **PPF terms:** a PPF instrument has `terms: { opened }`, the date the account was opened, which sets the 15-year maturity.
- **Batch member:** `import.apply` carries the `memberId` the file belongs to, for the per-member checks.
- **Signed keyring:** the keyring carries `sig`, an AES-GCM seal under DK of its SHA-256. Without it, anyone with access to the cloud folder could add revocations and lock every device out. A copy that fails the check is ignored and replaced at the next sync.
- **Snaps per device:** a device that compacts deletes only its own older snaps, and devices read every snap they haven't read yet, not just the newest. Otherwise two devices compacting at once could lose events.
- **Backups take over unsynced events:** a `.pvault` lists the backing-up device's chunks that were never uploaded. The restoring device appends those events as its own, so they still reach other devices if the old device is gone.
- **"Monthly history" tab:** Excel reserves the sheet name "History", so the export's history tab is called "Monthly history".
- **PPF importer per bank:** `ppf-statement` became `bob-ppf-statement`, because each bank's statement looks different. Bank of Baroda uses the same layout for savings accounts, so the importer only claims a file whose entries look like PPF: credits other than year-end interest are multiples of ₹50, and there's at most one withdrawal a year. Narrations can't be relied on, so a year-end credit is interest when its narration says so or when it isn't a multiple of ₹50.
- **Statement balances for PPF and EPF:** a holding now carries `balance`, the credited balance without interest still accruing. The balance check compares a statement with that, not with the value, so a mid-year statement doesn't raise a false mismatch. The import preview no longer compares units for PPF and EPF, since they have none.
- **Screens on shadcn-svelte:** the web app moved to shadcn-svelte on Bits UI in the Luma style, with Tailwind 4 (see [the UI redesign spec](../specs/2026-10-22-ui-redesign-design.md)). Base UI was asked for, but it is a React library. LayerChart replaces uPlot, and Inter (Latin and Latin Extended only) is bundled.
- **Re-imported records belong to the new import:** records restored from an Excel or JSON export get the new import's batch as their source, so the restore can be undone like any import.
- **Removing members and accounts:** removing an account also deletes its transactions and statement balances, and takes it out of groups, all in one write. Importing the same files again brings them back. A member can be removed only once they have no accounts, and a portfolio keeps at least one member.
- **Zip files:** `unzip` in `packages/core/src/import/zip.ts` reads stored and deflated entries with the platform's `DecompressionStream`, so no library is added. It skips folders, hidden files and macOS's `__MACOSX` copies. Password-protected zips and ZIP64 are refused with a message to unzip first.
- **EPF passbooks, read without seeing them:** `node packages/core/scripts/pdf-outline.ts <file.pdf>` prints a PDF's rows with every digit and every word that isn't a known label masked, so a user can share a statement's layout but not its contents. `epfo-passbook` was written from two such outlines. pdf.js reads the PDFs: the legacy build under Node, and the modern build inside the data worker, where it parses in the same thread and loads only when a PDF is added.
- **One passbook per member ID and year:** each PDF covers one financial year. The opening balance becomes a statement balance on its 31 March. Each row's employee and employer shares are EPF contributions and its pension share is EPS, and the year's interest is credited on 31 March. A current-year passbook states its closing balance at the year's end, so that balance is dated by the day the passbook was printed. Rows are checked against the year's totals and the closing balance, and a mismatch shows as a warning.
