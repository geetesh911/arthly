# Loans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track money owed to you and money you owe, with repayments, write-offs and due dates, and count them in net worth.

**Architecture:** Two new log entities (`loan`, `loanEntry`) replayed like every other record. A pure engine module (`engine/loans.ts`) works out balances, totals, rules and due dates; `summary()`, `portfolioAnalytics()`, `checks()` and the Excel export read from it. The data worker exposes loan reads and writes; three new screens (`/loans`, `/loans/new`, `/loans/[id]`) plus small changes to Home, Analytics, Add, More and the sidebar.

**Tech Stack:** TypeScript, Vitest, SvelteKit (hash router, static), Svelte 5 runes, shadcn-svelte Luma components, Comlink worker, Playwright (phone and desktop projects).

Spec: [2026-10-23-loans-design.md](../specs/2026-10-23-loans-design.md)

## Global Constraints

- UI copy is short, plain language. Section names: **Owed to you**, **You owe**. Screen: **Loans**.
- Test fixtures and sample data are synthetic ("Sample friend", "Sample relative").
- New data must be log events (it is: `entity.put` / `entity.delete`).
- `FORMAT_VERSION` becomes 2; the v1 → v2 upgrade is the identity.
- Net invested, total gain, XIRR, absolute return, weights and history stay investments-only.
- What you owe is never a chart slice.

    /** Below zero when more was paid back than lent. */

  export const NO_LOANS: LoanTotals;
  export function loansApply(filter?: Filter): boolean;
  export function loanStatuses(state: State, date: ISODate, filter?: Filter): LoanStatus[];
  export function loanTotals(statuses: LoanStatus[]): LoanTotals;
  export function loansDue(statuses: LoanStatus[], from: ISODate, days: number): { date: ISODate; loan: Loan; amount: number }[];
  export function outstanding(entries: LoanEntry[]): number;
  export function loanProblem(state: State, loan: Loan): string | undefined;
  export function loanEntryProblem(state: State, entry: LoanEntry): string | undefined;

- [ ] **Step 1: Write failing tests** (`loans.test.ts`) using `Ledger` from `testkit.ts`:
  - part repayment: lent 50,000 on 2026-01-10, repaid 20,000 on 2026-03-01 → on 2026-04-01 balance 30,000, open, start 2026-01-10.
  - settle: another repayment of 30,000 → balance 0, `open: false`, `settled` = its date; totals exclude it.
  - write-off counts like a repayment for the balance and is reported in `writtenOff`.
  - an entry dated after the day doesn't count yet.
  - overdue: due 2026-02-01, open on 2026-04-01 → `overdue`; settled → not overdue.
  - totals: one lent (30,000, member m1) and one borrowed (10,000) → `{ owedToYou: 30000, youOwe: 10000, owedToYouByMember: { mem_1: 30000 } }`; an overpaid loan counts as 0.
  - filters: `memberId` keeps that member's loans; `loansApply({ groupId: 'g' })` and `({ assetClass: 'equity' })` are false; `({ memberId })` and `{}` true.
  - `loansDue`: due within 30 days and open → listed with the balance; past or settled → not.
  - rules: `loanEntryProblem` refuses amount ≤ 0, a repayment above the balance ("That's more than the ₹30,000 still owed"), a repayment before the first advance; accepts an equal repayment. `entryRemovalProblem` refuses removing the advance while repayments exist. `loanProblem` refuses a blank party, an unknown member, and a due date before the start.

- [ ] **Step 2:** Run → FAIL (module missing).
- [ ] **Step 3: Implement** `loans.ts`:

  ```ts
  export const LOAN_EPS = 0.005;
  const byDate = (a: LoanEntry, b: LoanEntry) => a.date.localeCompare(b.date) || a.id.localeCompare(b.id);
  const signed = (e: LoanEntry) => (e.type === 'advance' ? e.amount : -e.amount);
  export const outstanding = (entries: LoanEntry[]) => entries.reduce((n, e) => n + signed(e), 0);

  export function loansApply(filter?: Filter): boolean {
    return !filter?.accountId && !filter?.instrumentId && !filter?.groupId && !filter?.assetClass;
  }

  export function loanStatuses(state, date, filter?) {
    if (!loansApply(filter)) return [];
    const entries = new Map<string, LoanEntry[]>();
    for (const e of all(state, 'loanEntry')) (entries.get(e.loanId) ?? entries.set(e.loanId, []).get(e.loanId)!).push(e);
    return all(state, 'loan')
      .filter((l) => !filter?.memberId || l.memberId === filter.memberId)
      .map((loan) => {
        const list = (entries.get(loan.id) ?? []).sort(byDate);
        const counted = list.filter((e) => e.date <= date);
        const sum = (t: LoanEntryType) => counted.filter((e) => e.type === t).reduce((n, e) => n + e.amount, 0);
        const [advanced, repaid, writtenOff] = [sum('advance'), sum('repayment'), sum('write-off')];
        const balance = advanced - repaid - writtenOff;
        const open = balance > LOAN_EPS;
        const start = list.find((e) => e.type === 'advance')?.date;
        return {
          loan, entries: list, advanced, repaid, writtenOff, balance, open,
          ...(start ? { start } : {}),
          ...(!open && counted.length ? { settled: counted.at(-1)!.date } : {}),
          overdue: open && !!loan.due && loan.due < date,
        };
      });
  }
  ```
  `loanTotals` sums `Math.max(0, balance)` of open loans by direction; `loansDue` keeps open loans with `from <= due <= addDays(from, days)`, sorted by date. `loanEntryProblem` builds the loan's other entries (`id !== entry.id`), then applies the rules with `inr()` money text (`₹${Math.round(n).toLocaleString('en-IN')}`). `entryRemovalProblem` checks `outstanding(rest) < -LOAN_EPS`.
- [ ] **Step 4:** Run → PASS.
